# Web Camera Tracking

Public site: https://lorah101204.github.io/Finger_And_Face_Tracking/ (open the app directly: `https://lorah101204.github.io/Finger_And_Face_Tracking/#/app`). Repo: https://github.com/Lorah101204/Finger_And_Face_Tracking.

A white pixel screen divided into cells; the reveal region is the convex hull of the fingertips of both hands; face tracking and person/mannequin classification run only on the reveal region. All inference runs in the browser; the app is static files with no backend, and nothing leaves the browser (D-019): project code never calls a server, third-party library `fetch` is blocked cross-origin right inside the worker (D-050), and the service worker blocks it once more. The static host (GitHub Pages) still logs visitor IPs under GitHub's policy like any web server; the app sends nothing else.

## Requirements

- Node.js 20 or newer (built with Node 24).
- Recent desktop Chrome or Edge for the PoC.
- Python 3 is needed only for the scripts in `tools/` (TEST-00, CLS-01, CLS-02).

## Run

```bash
npm install
npm run models:fetch
npm run dev
```

`npm run spikes:fetch` re-downloads MediaPipe's public sample images into `public/spike-assets/` (`face.png`, `hands.jpg`; not committed) for the local e2e test cases on a real face and real hands; when they are missing those cases skip themselves. `npm run models:fetch` downloads `hand_landmarker.task` and `face_landmarker.task`, copies the `@mediapipe/tasks-vision` wasm and the `onnxruntime-web` wasm loader into `public/models/` according to `public/models/models.json` (source, version, sha256), and generates the stub model `classifier-stub.onnx` (CLS-02). Models are not committed to git; the app has no CDN dependency at runtime.

`npm run dev` runs Vite at http://localhost:5173. Routing is hash-based (D-020): `/` (or `/#/`) is the landing screen (UX-02, D-042; refined in UX-03, D-049): the name, a one-sentence introduction, an animated illustration drawn on canvas (no camera, no images), three privacy commitment lines, a versioned consent box, the "Bắt đầu" (Start) button and a three-step stepper on a single screen at 1280 × 720 or larger, no external fonts or images, no camera call yet; `/#/?mode=present` is the kiosk version (grid covering the whole screen, floating consent card) that leads into presentation mode; `/#/app` is the white canvas stage with camera selection and the "Bật camera" (Start camera) button (only after consent). Screenshots are in [docs/screenshots/](docs/screenshots/) (`npm run screenshots`). The consent choice is stored in the browser together with the text version; when the text changes, bump `CONSENT_VERSION` in `src/app/session.ts`. The storage scope is set in `DEFAULTS.consent.scope` in `src/core/config.ts`: `device` (localStorage, default) or `tab` (sessionStorage, expires when the tab closes, for kiosk; D-021).

Camera (CAM-01): click "Bật camera" (Start camera) at `/#/app`; `CameraSource` calls `assertCameraAllowed()` before `getUserMedia`. The video element is in the DOM but hidden and the canvas stays white: this layer does not draw video, only MASK-01 draws it and only inside the reveal region. The control bar shows the status, `epoch`, `frameId` and the camera-related close reason; `window.__wct.camera.probe` counts frames and checks that `frameId` is continuous. A hidden tab and no frame for more than 500 ms are reported so the loop (INT-01) closes the reveal region.

Grid (GRID-01): DPR-aware canvas (`ResizeObserver`), cell size `c = floor(min(W / cols, H / rows))`, centered board, camera mapped cover-style; presets 32 × 18, 64 × 36, 128 × 72 or custom 4..256 × 4..144; grid lines and mirror can be toggled. All Cam, Stage, Cell transforms live in `src/core/coords.ts`; settings and layout live in the store `src/loop/store.ts`, readable via `window.__wct.stage.snapshot()`. Changing the grid, mirror, window size or camera all increment `epoch` (D-026).

Mouse window (ROI-00, a debug mode kept permanently): clicking on the board opens an 8-cell window at the pointer, drag to move, mouse wheel to resize, Esc closes, Space reopens. The window is always square and clamped inside the board (red border when clamped). The loop `src/loop/frameLoop.ts` runs on rAF: window source → `stepReveal` (`src/core/revealState.ts`, epoch rules in section 4.6) → `buildMask` (the only function that creates a mask) → draw background, grid, border; no video yet (MASK-01). The reveal region state is read via `window.__wct.loop.snapshot()` (D-027).

Mask and compositor (MASK-01): `render` in `src/mask/compositor.ts` is the only place that draws the camera onto the output, only from the mask's `cameraRect` into `stageRect` inside `ctx.clip`, with mirror flipping within the window; without a mask no video is drawn. Every frame is fully redrawn, so old cells close on their own when the window moves. `check:invariants` checks that `drawImage` appears only in the compositor and `restrictedFrame`, always with a source rect (D-028).

Debug and test (TEST-00): open `/#/app?debug=1` to get the probes `window.__wct.probes` (`onOutputFrame`, `onRestrictedFrame`, counters) and the scenarios `window.__scenario.run('windowAt(col,row,n)')`, `moveWindow`, `resizeWindow`, `coverAll`, `delayWorker(ms)`, `faceMaxAge(ms)` (QA-01, relaxes the maximum age of face results); add `&source=synthetic` to replace the camera with the synthetic source (left half green, right half magenta, changed with `__scenario.scene({...})`) without calling the real camera. The y4m clip for Playwright's fake camera: `python tools/make_test_clips.py` (needs ffmpeg; `--dry-run` prints the command), writes `tests/e2e/fixtures/camera.y4m`, not committed (D-029).

Restricted buffer (MASK-02): `createRestrictedFrameBuilder` in `src/mask/restrictedFrame.ts` is the only place that creates a `RestrictedFrame` for the face worker and the classifier worker: a 1:1 crop of exactly `cameraRect` into a separate OffscreenCanvas, then a 256 × 256 letterbox with gray padding 128 from the crop canvas and `transferToImageBitmap`, one bitmap per worker. The source is a `FrameSource` (hidden video or synthetic canvas), never the output canvas; the buffer is in camera space, not mirrored. The loop creates buffers at the `face.targetHz` rate while the region is open; when the short side is under 64 px it is `too-small`, no task is created and the debug bar suggests enlarging. There is no worker yet, so the bitmap is closed immediately (INT-01 connects it). The `onRestrictedFrame` probe (with `?debug=1`) receives an `ImageData` copy right before the transfer; the e2e hard gate measures at the probe, not on screen (D-030). Letterbox math and the inverse mapping are in `src/core/letterbox.ts`.

Face worker (FACE-01): `src/face/face.worker.ts` is a module worker running Face Landmarker (IMAGE mode, GPU with CPU fallback, warm-up on a gray image) and accepts only `RestrictedFrame` via the `detect` message (protocol in `src/face/faceProtocol.ts`). `FaceClient` initializes the worker when `/#/app` opens, sends one task at a time, drops when busy, calls `rejectAll` when the region closes or the epoch changes, and sends at a rate of `max(1000 / face.targetHz, p50 inferMs)`. The loop counts `faceDetectSubmitted` and `faceDetectDropped` into the probe. The debug bar shows the worker status; with `?debug=1` there is a thumbnail of the buffer just sent (visual evidence that the model only sees the reveal region) and `window.__wct.face.snapshot()` (D-031). Results are validated and drawn in FACE-02.

Face gate and overlay (FACE-02): returned results are checked by `validateFace` (`src/face/faceValidate.ts`) against the epoch, age (250 ms from the sent frame), the current mask and rejected taskIds; each face maps its landmarks from the letterbox image back to camera space via the task's ROI and then to stage; a face fully inside the ROI shrunk by 4% and inside the mask is `full`, one intersecting the mask is `partial` (dashed bbox), one not intersecting is dropped; landmarks keep only points inside `stageRect`. The overlay is drawn inside `clip(stageRect)`, so there is never an overlay pixel under the white area; on close or epoch change the face disappears on the very next frame. The states `covered`, `searching`, `too-small`, `face-candidate`, `partial-face` show in the bottom bar; `FrameOutput` is emitted every frame via `window.__wct.loop.events` (the `frame` event) and readable at `loop.snapshot().output` (D-032).

Hand landmarker and hand IDs (HAND-01): when the "Tay" (Hands) window source is selected, the loop sends the raw frame (allowed by the read-permission table) to `src/hands/hand.worker.ts`, a module worker running Hand Landmarker in VIDEO mode (delegate `auto`: GPU on hardware, CPU when WebGL is a software renderer, D-045); `HandClient` is the only place in `src/` that calls `createImageBitmap` (checked by `check:invariants`), one frame at a time. `normalizeHandedness` keeps the model's label unchanged for the raw frame (D-010); if a real webcam gives inverted labels, enable "Đảo trái/phải" (Swap left/right) on the control bar. `HandTracker` matches detections to tracks by palm-center distance plus a penalty for a differing label, keeps ids stable, marks `uncertain` when two matching options are close, and removes a track after 150 ms unseen. The debug overlay draws the id and left/right next to each hand on the white background (no camera drawn); `window.__wct.hands.snapshot()` is for e2e. When no hand is seen, the "Tay" source closes the region with `few-points` (D-033, reason renamed in D-047); the hand window exists from ROI-01. The 10-second check with a real right hand per D-010 could not be done on the development machine: it needs one manual try with a webcam.

Fingertips of the whole hand (ROI-03, replaces the four slots of HAND-02, D-047): `src/hands/fingertips.ts` evaluates every selected fingertip (default all five: thumb 4, index 8, middle 12, ring 16, little 20) of every hand in the latest `HandFrame`, with points mapped to stage; a point is valid when fresh (point age per sensitivity), inside the board, the hands are not crossed and the handedness label is confident enough; invalid points are only excluded from the region (reasons `stale-point`, `out-of-board`, `ambiguous-hands`, `low-score` recorded in `FrameOutput.points`, one element per fingertip). The region closes when fewer than 3 valid points from 2 hands remain: `few-points` (no hand seen yet, a hand missing, few fingers selected) or the dominant reason among the invalid points. The "Đầu ngón dùng" (Fingertips used) bar (only when the source is hands) drops fingers for both hands, and a change does `epoch++`; `hands.minHands` in `core/config.ts` set to 1 gives one-hand mode. Dots colored per hand are drawn on the white background, faded when the point is stale; the status message states the point count and the missing hand ("Đang thấy 5 đầu ngón hợp lệ, cần ít nhất 3 của 2 tay: chưa thấy tay phải", roughly "Seeing 5 valid fingertips, need at least 3 from 2 hands: right hand not seen yet").

Hand-driven reveal region (ROI-01, revised in ROI-02 per D-038 and ROI-03 per D-047): `HandWindowSource` (`src/reveal/handWindowSource.ts`) is the "Tay" (Hands) window source: every frame it evaluates the fingertips, closes with the reason per section 5.8 when there are not enough points, and otherwise `solveHull` (`src/reveal/hullSolver.ts`) One Euro filters each coordinate keyed by point (`src/reveal/oneEuro.ts`), takes the **convex hull** of the valid points (`convexHull` in `src/core/cells.ts`), and closes with `too-small` when the short side of the bounding box is under `nMin` cells or the area is too small. `buildMask` rasterizes the polygon into a **cell set**: cells inside the polygon or cut by an edge are all open, with a hysteresis of 0.25 cells (an open cell only turns off when the polygon moves farther than 0.25 cells away, a closed cell only turns on when it is penetrated deeper than 0.25 cells); cells in the bounding box that are not open are holes: they stay white on the output and are filled with gray padding in the inference buffer. It solves only once per new `HandFrame` and restarts on closed → open or a config change. The "Độ nhạy" (Sensitivity) bar (only when the source is hands, UC-09) adjusts minCutoff, beta, hysteresis, N min and point age, applied immediately without changing the epoch. The debug scenario `window.__scenario.hands(spec)` replaces the hand worker with two fake hands (`src/debug/fakeHands.ts`) and `fingers(4,8)` selects fingers so e2e can test the hand-driven region without real hand images (D-035, D-036, D-038, D-047). The square window remains only in mouse mode.

Performance (PERF-01): the "hiệu năng" (performance) line on the debug bar and `window.__wct.stats.snapshot()` read a 250 ms sampler (`src/debug/stats.ts`): output fps, hand, face and classifier Hz over a 2 s window, p50/p95 inferMs (`src/core/latency.ts`, `p95InferMs` in FaceClient and HandClient), loop draw and tick time, dropped buffers, pending tasks, epoch, state. Rate control: the face worker takes one task at a time at a rate of `max(1000 / targetHz, p50)`, the hand worker receives a new frame when idle; React only reads via `useSyncExternalStore` at 4 Hz. Soak and benchmark: `npm run test:soak`, `npm run bench:report`, results in [docs/benchmark.md](docs/benchmark.md) (D-040).

Hand and face integration (INT-01): the "Tay" source goes through the same loop as the mouse: hand window → `buildMask` → restricted buffer → face worker, so faces only appear inside the region the hands open, and dropping one hand closes the region in the same frame, the face and label are cleared, and the face worker stops receiving buffers. Changing the window source is a config change (`epoch++`, close with `config-changed`). `CloseGate` (`src/loop/closeGate.ts`) closes the region with `no-camera` when the camera stops, the camera changes or the watchdog sees no frame, and with `tab-hidden` when the tab is hidden: it closes immediately inside the event (`requestAnimationFrame` does not run when the tab is hidden) and also on every frame; once the reason is gone the window reopens with a new epoch (D-037). Running the full set of section 7 scenarios with real hands on the development machine could not be done: it needs one manual try with a webcam (together with the D-010 check).

Status and guidance (UX-01): the guidance layer floating under the canvas states the current step (1 Camera, 2 Cửa sổ, 3 Khuôn mặt; i.e. Camera, Window, Face), a title and one sentence saying what to do next for each camera phase (not started, requesting permission, switching camera, no frames delivered, tab hidden, stopped, error), each close reason (which fingertip is missing, lost track, out of the board, too close together, crossed hands, settings just changed, mouse) and each reveal region state (searching, too small, face seen, face cut off, touching the edge); messages are computed in `src/app/guidance.ts` (pure, with unit tests covering every reason). The "Toàn màn hình" (Fullscreen) button (key F) puts the canvas on the whole screen, the top bar and panels become an overlay that hides itself after 2.5 s without interaction (the canvas is not resized, so the reveal region does not close). The settings panel and debug panel collapse from the top bar; the state is kept in the tab's sessionStorage; the debug panel is open by default only with `?debug=1` (D-041). The current layout of the two panels is in the UX-03 paragraph below.

Dataset mode (CLS-01, D-043): in the settings panel tick "Thu dữ liệu" (Data capture), confirm that the participant has signed the consent form (template in [docs/dataset.md](docs/dataset.md)), fill in the anonymous code, provisional label and conditions, then "Bắt đầu thu" (Start capture): while the reveal region is valid, the app saves the reveal-region crop (exactly the image the face worker receives, before letterbox, never the raw frame) with JSON metadata at 2 Hz into a folder you choose (File System Access API) or a downloadable zip; a red indicator shows on the canvas while capturing; nothing leaves the browser. Labeling, per-participant split (with leakage check) and statistics tools are in `tools/dataset/` (Python 3, standard library): `python tools/dataset/label.py check data/dataset`, `python tools/dataset/split.py data/dataset`, `python tools/dataset/stats.py data/dataset --doc docs/dataset.md`; tests: `python -m unittest discover -s tools/dataset`. There is no real data yet (participants and a mannequin are needed).

Person and mannequin classification (CLS-02, D-044): `src/classify/classifier.worker.ts` runs ONNX Runtime Web (webgpu when available, otherwise wasm) in a module worker, initialized lazily when the region first opens, and accepts only `RestrictedFrame` like the face worker; the loop sends a second bitmap of the same crop at 3 to 5 Hz when the reveal region side is ≥ 96 px; results pass through the same epoch, age and reveal-region gate and are then attached as a label to the face by the unknown rule (`src/classify/subjectRule.ts`: below 0.7, small ROI, heavily cut face → "Khuôn mặt chưa phân loại", i.e. unclassified face); the label is drawn on the face bbox and stated in the guidance layer. There is no trained model yet: `npm run models:fetch` generates `public/models/classifier-stub.onnx` (green → Người, magenta → Hình nộm; i.e. person and mannequin) to test the pipeline; the training script, ONNX opset 17 export, export check and evaluation per section 7.3 are in `tools/train/` (needs `tools/train/requirements.txt` and a real dataset), report in [docs/classifier-report.md](docs/classifier-report.md). While the stub is the configured model (`isDemoClassifier()` in `core/config.ts`), every label carries the suffix " · demo" and the guidance says the label comes from a color-based demo model, so the public site does not pass the stub off as real classification.

Local log (LOG-02, optional, D-022, D-046): ticking "Ghi nhật ký cục bộ" (Write local log) in the settings panel (off by default, stored in the browser) makes the app write metadata events into the browser's own IndexedDB `wct-log`: consent (version, scope), camera start/stop/error, region open (source, shape, cell box) and close (reason), config changes; each record is `{ ts, type, payload }` with payload ≤ 1 KB, never a frame, crop, landmark or image (`src/log/**` may import only `core/**`). At most 10 000 records or 30 days, oldest deleted first. Buttons "Xem nhật ký" (View log; filter by type, by day), "Xuất CSV" (Export CSV; download, `ts,time,type,payload`) and "Xóa nhật ký" (Clear log); the top bar shows `nhật ký bật · N` (log on · N) while it is on. Nothing leaves the browser.

Benchmark and device matrix (QA-02, D-045): the URL parameter `hands=GPU|CPU` picks the hand worker delegate and `ep=wasm` forces ONNX Runtime to use wasm (default webgpu when an adapter exists, otherwise wasm) for comparison on the target machine, for example `/#/app?hands=GPU`; the "môi trường" (environment) line in the debug panel (and `window.__wct.env.snapshot()`) lists the browser, thread count, WebGL GPU and missing APIs (rVFC, OffscreenCanvas, module worker, ImageBitmap, WebGPU, wasm SIMD, SharedArrayBuffer, fullscreen, directory picker, getUserMedia) for checking Firefox or Safari by hand when they cannot be installed for Playwright. `npm run test:bench` then `npm run bench:report` writes the matrix into [docs/benchmark.md](docs/benchmark.md); the locked parameters (point age, result age, label age, hysteresis, hand delegate) live in `src/core/config.ts` with the reasoning in section 6 of that document.

UI (UX-03, D-049): `src/app/app.css` is the shared token set (32 px controls; the default button is an outlined secondary button, `.primary` only for primary actions such as "Bật camera", "Bắt đầu", "Bắt đầu thu" (Start camera, Start, Start capture), `.danger` for deletion; switches, chips, status pills; no external fonts or images, the select arrow is an SVG data URI). The top bar has three zones on one line at 1280 px: brand (link back to the landing page) and camera | camera status pill with a dot colored per phase (still `role=status` with the full sentence, truncated with an ellipsis) | "Cài đặt", "Debug", "Trình diễn", "Toàn màn hình", "Thu hồi đồng ý" (Settings, Debug, Present, Fullscreen, Revoke consent). Settings is a 320 px column on the right divided into sections ("Lưới", "Cửa sổ", then "Đầu ngón" and "Độ nhạy" only when the source is hands, with sliders and number fields, "Thu dữ liệu", "Nhật ký cục bộ"; i.e. Grid, Window, Fingertips, Sensitivity, Data capture, Local log); Debug is a drawer under the canvas (three-column mono grid, at most 150 px). Both are in the layout flow: collapsing the column returns its width, opening the drawer takes height (epoch++, an open window closes). Presentation mode (the "Trình diễn" button, or opening `/#/app?mode=present`; stored in the tab's sessionStorage) uses the fullscreen overlay mechanism for all three: the top bar becomes a floating pill, the settings column becomes a glass sheet on the right, debug becomes a HUD at the top left, guidance uses large text; the canvas fills the whole screen, so opening a panel does not resize the canvas and does not close the window; after 2.5 s without interaction the floating layer hides, leaving one hint bar at the top edge. The landing screen has the animated illustration `LandingPreview` (geometry in `landingScene.ts` uses the app's own `convexHull`, `rasterizePolygon` and full/partial face rule) and the kiosk version `/#/?mode=present`.

Deployment (REL-01, D-048, D-050): `npm run build` produces a `dist/` of about 80 MB (`models/` 76 MB with the models, the MediaPipe module wasm and two ORT loader pairs; `assets/` 1 MB; `sw.js`; no `spike-assets/`), to be put on any HTTPS static host (the camera needs a secure context). No SPA fallback is needed thanks to hash routing. There are no runtime environment variables; at build time `VITE_BASE` sets the page's base path (default `/`, of the form `/name/` when the page is at `https://<user>.github.io/<repo>/`; every model path goes through `withBase()` in `src/core/config.ts`). The service worker `public/sw.js` (production build only) caches models and wasm into `wct-models-<khóa theo models.json>` (key from models.json) and assets into `wct-app-<khóa theo build>` (key from the build), starting from the first load (the page sends the list of what it loaded), so later loads do not re-download the models and the app opens offline; verified with `npm run test:deploy` on `dist/` itself. CI (`.github/workflows/ci.yml`): the `check` job builds with `VITE_BASE` from the repository variable `PAGES_BASE` (default `/<repo>/`), runs `test:deploy`, then the `deploy` job puts `dist/` on GitHub Pages after every push to `main` (Settings → Pages → Source: GitHub Actions); a custom domain is attached after purchase, then set `PAGES_BASE` = `/`. Public address: https://lorah101204.github.io/Finger_And_Face_Tracking/ (app: `https://lorah101204.github.io/Finger_And_Face_Tracking/#/app`); rollback steps and measurements are in [docs/deploy.md](docs/deploy.md).

HTTPS for trying it from another machine on the LAN: set `VITE_HTTPS=1` before running dev (PowerShell: `$env:VITE_HTTPS='1'; npm run dev`). Not needed on localhost, which is already a secure context.

## Testing and lint

```bash
npm run lint
npm run lint:boundaries
npm run check:invariants
npm run test:unit
npx playwright install chromium
npm run test:e2e
npm run test:report
npm run test:soak
npm run test:bench
npm run bench:report
npm run build
npm run test:deploy
```

- `lint:boundaries` checks the import rules of `src/face/**`, `src/classify/**` (invariant I1), `src/dataset/**` (I8) and `src/log/**` (LOG-02): only `core/**`, the model libraries and files in the same folder; configured in `eslint.boundaries.config.js`.
- `test:report` (QA-01, D-039) runs unit and e2e with the JSON reporter (`reports/unit.json`, `reports/e2e.json`), then `tools/test-report.mjs` generates the "Run results" section of [docs/test-report-mask.md](docs/test-report-mask.md): environment, Chromium and model versions, a per-case table with the measurements the tests write into annotations (`note`, `expectGateClean` in `tests/e2e/helpers.ts`). `test:report:write` only regenerates from existing JSON. The hard gate is measured in two independent ways in every case that uses the synthetic source: marker colors (`restricted.spec.ts`) and a per-pixel comparison against a reference image rebuilt from the scene definition (`installGateAudit`). CI: `.github/workflows/ci.yml` runs the whole chain on Linux with Playwright's Chromium (2 workers, one retry), caches models by the sha256 in `models.json`, and stores `reports/`, the report and `dist/` as artifacts; cases that need local assets skip themselves there.
- `test:soak` (PERF-01, D-040) runs a soak of `SOAK_MINUTES` minutes (default 15) with `playwright.soak.config.ts`: the hand-driven reveal region and the face worker run continuously, and every `SOAK_SAMPLE_S` seconds (default 30) it samples stats, heap after GC, nodes and listeners via CDP; it asserts that memory does not grow steadily, fps is stable, pending tasks ≤ 1, no page errors; raw samples are in `reports/soak-samples.json`. `bench:report` (`tools/benchmark-report.mjs`) writes the target table and samples into [docs/benchmark.md](docs/benchmark.md). Do not run the soak in parallel with `test:e2e` (same port 5174).
- `test:bench` (QA-02, D-045) runs `tests/bench/bench.spec.ts` with `playwright.bench.config.ts` on every browser available on the machine: Playwright's Chromium headless shell (SwiftShader, lower bound), installed Chrome and Edge (via `channel`, real GPU even headless), Firefox and WebKit after `npx playwright install firefox webkit`; `BENCH_SECONDS` seconds per measurement (default 20), `BENCH_BROWSERS=chrome,msedge` selects browsers, `BENCH_HEADED=1` shows the window. Four cases: environment (browser, WebGL GPU, WebGPU adapter, APIs the app relies on, face worker), mouse window on `face.png` or the synthetic background (fps, face and classifier Hz, result interval and age when the gate accepts, over-age results), classification forced to wasm (`ep=wasm`) for comparison with the default EP, real hands on `hands.jpg` with the CPU then GPU delegate (`hands=CPU|GPU`; Hz, result interval, fingertip jitter on a still image). Raw results in `reports/bench-<project>.json`; `bench:report` merges them into `docs/benchmark-matrix.json` and the "Device and browser matrix" section of [docs/benchmark.md](docs/benchmark.md) with a table comparing the locked parameters against the measurements. Do not run in parallel with `test:e2e` or `test:soak`.
- `test:deploy` (REL-01, D-050) runs `tests/deploy/sw.spec.ts` with `playwright.deploy.config.ts` on the production build `dist/` via `vite preview` (port 4174; run `npm run build` first, with the same `VITE_BASE`): the cache keys in `dist/sw.js`, old caches deleted on activation, the first load caches all models, wasm, the ORT loader for the EP and the assets, on the second load every response comes from the service worker with no network access, the third load still runs offline, no cross-origin requests; the `chromium` project (wasm, jsep loader) and `chrome` when the machine has Chrome (WebGPU, asyncify loader). Results in `reports/deploy.json` go into their own section of `docs/test-report-mask.md`.
- `check:invariants` (`tools/check-invariants.mjs`) checks that `getUserMedia(` appears only in `src/camera/cameraSource.ts` and after `this.#gate()` (I10); that `src/` has no `fetch(`, `sendBeacon`, `WebSocket`, `XMLHttpRequest`, `EventSource` (I9) and every `*.worker.ts` plus `main.tsx` calls `installSameOriginGuard(` (D-050); that `drawImage(` is only in `src/mask/compositor.ts` and `src/mask/restrictedFrame.ts`, always with 9 arguments (I2, I4); that `src/mask/restrictedFrame.ts` does not touch the DOM and crops from `source.drawable` (I1, I3); and that `createImageBitmap(` (full-frame raw frame) is only in `src/hands/handClient.ts` (I1).

## Import rules

`src/face/**` and `src/classify/**` must not import `camera/`, `hands/`, `reveal/`, `mask/`, `app/`, `loop/`, `debug/`; they may use only `core/**`, the model libraries and files in the same folder. This is how the source code guarantees that the face model and the classifier model never see the raw frame. `src/dataset/**` (I8) and `src/log/**` (LOG-02) may also import only `core/**`.

No code calls a server: no `fetch`, `sendBeacon`, `WebSocket` to an API (invariant I9); third-party library `fetch` in workers and the page is restricted to same-origin by `src/core/networkGuard.ts` (MediaPipe tasks-vision sends usage statistics to Google if not blocked, D-050). `getUserMedia` may only be called in `src/camera/cameraSource.ts`, right after `gate` (the app passes `assertCameraAllowed` from `src/app/gate.ts`), from the button click handler at `/#/app` (invariant I10, D-025). Both are checked by `npm run check:invariants`.

## Technical spikes

Spike code lives in `tools/spikes/` and runs on the dev server (`http://localhost:5173/tools/spikes/s1.html` through `s6.html`); measurements and method are in [docs/spikes.md](docs/spikes.md), the resulting decisions in [docs/decisions.md](docs/decisions.md). Spike assets (`public/spike-assets/`) are downloaded by script, not committed. `node tools/spikes/run-spike.mjs s5` runs one page in headless Chromium and writes JSON into `docs/spikes/raw/`.
